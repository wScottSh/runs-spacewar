# The PDP-1 declarations

`tools/runsc.py` compiles the RUNS source in `runs/` to the original Spacewar! 3.1 tape image. It is the PDP-1 back end for any program: `RUNS_PROGRAM=programs/minskytron` names another program's directory, which holds its own `runs/`, `pdp1/` and `lift.toml` (its units, its oracle's sha256 and listing), and the image is built under `build/<name>/`. Each file here holds the declarations for one unit of `lift.toml`, the one its name names (`main_loop.toml` for `lift/main_loop.c`): it says how the PDP-1 carries the RUNS routines and fields of that unit. `runsc` emits the lift's C dialect from the RUNS source and the declarations, and `tools/pdp1cc` compiles that to the image. Every unit has a program's declarations: the generated C stands alone, and no file of `lift/` takes part in the build (`build/runs/lift` holds only the thirteen generated files).

These files are the half of the PDP-1 package that never runs. They record the 1962 programmer's arbitrary choices about where the game's data lives and how routines are called; a Port, which swaps the Realization Processors and keeps the Rules region (`../../.github/CONTEXT.md` 313-320), leaves them behind with the PDP-1 Realization Processors. They are not a place to solve what is hard to write in RUNS: `tools/check_declarations.py` (in `check_all.sh`) counts their entries, every scalar value and every list element of the TOML (an empty table or list is one), and fails a commit that adds one, a name added to an existing list included; only the user raises the count in `pdp1/DECLARATIONS`. A commit that removes entries lowers it. The code keeps the old name (`Bindings`, `BindError`).

## What a program's declarations may say

A program's declarations hold only choices that play cannot observe:

- **Tape order.** `[[place]]` entries in the order their words lie on the tape: a routine, or a list of Record fields.
- **Calling convention.** How a routine is entered and left: `JDA`, `JSP`, `BLOCK`, `XCT`, laid out in place, a skip return.
- **Storage.** Which register or word carries a value: an AC or IO local, a JDA entry word, a pool word, the address field of an instruction (a cursor), the word after a call (by name).
- **Layout of code.** Where a block of a routine's code lies when the original lays it out of order.
- **Devices.** Which console instruction or sense switch holds each input field, which program flag lights for each output field, and at which address the operator starts each top Network. This is the Realization side of the boundary Records: play sees the input's value and the output's value, never the device, and a program's declarations for another machine map the same fields to its own controls and lights. All of it is in one file, `pdp1/devices.toml`, which `runsc` and the checks (`tools/pdp1.py`) both read; no other file names a switch, a light or a start address.

## The vocabulary

A `[[place]]` with `fields` lays out those Record fields as data words, with their RUNS initial values. A `[[place]]` with `routine` compiles a Processor or a Network to one C function:

- `convention`: `JDA`, `JSP`, `XCT`, as the lift's dialect names it (`tools/pdp1cc/include/pdp1.h`). An `[[inline]]` entry takes the same keys and declares a macro: the routine is laid out at each run, as a `static inline` function of each unit that runs it, whichever file declares it.
- `entry`: the field that is the JDA entry word, where the call leaves AC.
- `byname`: the field that is the word after the call, executed each time it is read.
- `result`: the fields that hold the result when the routine returns: AC, then IO.
- `io_param`: the field that arrives in IO.
- A called Processor with no entry word (`XCT`, `INLINE`, `JSP`) declares none of `io_param` and `result`: `runsc` takes them from the source. Its parameters are the register fields it reads before it writes them, its results the register fields it writes, AC's then IO's. A field lives in IO when `io` names it or the source sets it as the second half of a pair (`set (handoff.jump_high, handoff.jump_low) = scl(...)`, the machine's AC:IO pair); a field it reads and writes arrives where it leaves. Minskytron's pick does the same: `rcl` takes the bits in IO, and the count comes back in AC (`gsh`).
- `io`: locals and fields that live in IO. The rest live in AC or in a word of their own. A local set from a value already in IO is that value, with no move.
- `cells`: other fields that live in the routine's entry word.
- `skips`: a field and a member: the routine returns one word further when the field holds the member.
- `block`: the routine's body is a block that other routines of the unit jump into. The routine's own entry stores its entry word and jumps there too. A run of the routine as the last thing another routine of the unit does is that jump: the jumper stores the entry word, as jda would have.
- `block_takes_entry`: the block is entered with the entry word already in AC (`sin` loads it; `cos` jumps in past the load).
- `shifts = "xct"`: each shift of the routine is executed from a constant word (`xct (sar 3s`), as the `diff` macro runs the shift it is passed.
- `pool`: locals that live in a pool word (`\hpt`), not in AC.
- `loops = "exit first"`: each loop of the routine is laid out with its first exit falling through into the code after the loop, and the rest of its body after the routine's last return, jumping back to the top. When the loop's body ends with the statement that an `if` just before the loop runs, that statement is the loop's top, and the loop is entered there or one statement past it. It changes the order of the code, not what runs.
- `convention = "BLOCK"` on a Network: a block that others jump to. A `run` of it is a jump, and it must be the last thing its branch does. A routine that names no convention is a BLOCK when every run of it is the last thing a declared routine does (once the routines it runs inline are laid in), or nothing runs it and it is started or repeated; any other names its convention. DDT's listen block is entered only by jumps (`jmp lse`) and its start (`start lis`); Minskytron's start and its repeated pass are blocks.
- `inline`: the field that is the constant word after the call (`jda oc / ot1`).
- `io_reads`: fields a guard of the routine reads into IO, because AC holds a value the routine still needs (`lio ddd`, `lio i \mfu`). IO has only a sign test (`spi`), so it applies to a guard that tests the sign, of a field or of a field at a slot.
- `spill`: AC locals kept in a pool word from their last set on, and read from there (`dac \mt1`).
- A `JSP` Processor whose result field is in `io` returns in IO (`io_word`).

A `[[code]]` entry declares a walker over a collection held as a run of code (`held_as_code` on a collection field of an enum, below): a Processor whose body is `let at = <slot>`, then a loop that takes the slot's member (`let m = L.f[at]`), runs that member's arm of an if-chain, and steps on (`set at = at + 1`) (`draw_outline` over `outline_code.stroke`). It has no code of its own: each slot's words are its member's arm. Its run is a jump to the words of the slot it starts from, and the run the RUNS source makes right after it is where a `break` of an arm jumps, so that run compiles to nothing. An arm goes on only to the next slot (it runs off its end into the next member's code) or from a place a held field of the slot holds (`set at = L.g[at]; continue`, the jump held there). It is a calling convention. `io` names the walk's locals and register fields that live in IO; the rest live in AC.

- `pulse = true`: the code waits for the display's completion pulse before its first point and leaves its last point's pending. So the point the RUNS source plots just before the run asks for a pulse (`dpy-4000`, at intensity 0), and the routine the code jumps back to waits for it first (`ioh`). It is the display's handshake, which play cannot observe.

A code entry a walk carries (`carry`) is reached through its home: its run is a jump through the homed word (`sp5, jmp .`), and the unit that runs it holds the home.

A Network declared as one routine runs its Processors inline, under its guards and loops. A `run` of another declared routine is a call: the sets of that routine's parameter fields just before the run are its arguments, and a parameter field that lives in a register is passed in it. A two-word result is read from the returned AC:IO pair. A one-word result is in AC when the call returns, so the statement right after the run takes it from there, as `xct hd2 / dac i ma1` does; when that statement does not read it, the call stands alone.

The keys that hold for a whole unit:

- `registers`: Records whose fields live in AC or IO, never in a word of their own. A field there is a local of the routine that uses it. A Record none of whose fields the declarations give a place (a word, an entry word, a pool word, a device or flag, an address, a cursor or an instruction) is one already (`handoff`, `outline_point`; Minskytron's `shift_pick`, which its pick returns in AC and IO), so `registers` names only a Record that also has such a field (`outline_call`, whose code is the outline compiler's entry word).
- `pool`: fields that live in a pool word (`\mxc`).
- The cursors are not declared; `runsc` takes them from the source. A walk is a Network's loop over the table's slots from 0 (`for slot in 0 .. 026`). Its cursors are the fields indexed by its slot variable, or by a routine's parameter that a run passes it in, through calls and match arms: in such a routine `objects.x[slot]` is `*objects_x_slot`. A walk from the slot after another's (`for other in slot + 1 .. 027`) has cursors of its own, the fields its variable indexes the same way. A field that holds a slot and indexes table fields (`launch.slot`) has a cursor on each, homed in the one unit whose routines index by it. A cursor is named for its field and the variable. The music player does the same: its compile loop sets a pointer for each voice field it reads at voice `ij`, in the layout's order, and none for the bar pointer it does not read there (`pdp1m16` `cc1`: `law b / add ij / add (n-b / dap c0n / add (t-n / dap c0t ...`).
- `held_as_code`: fields held as the compiled code of their use (`docs/rules/held-as-code.md`): written at one stage and read at a later one, by different Processors, and stored as the words the use compiles to. For a count, the use is the operator that takes it as its count: a pair operator (the pair it shifts is one AC:IO local), `>>`, `<<`, `ral` or `rar`. `runsc` emits that use as a `TEMPLATE` function with the count its `VALUE`, and `pdp1cc` compiles it to one shift instruction: the word a store of the count stores, `CODE(t, n)`. A field that only reaches a shift through copies (a table the count is picked from) shares its copies' template, and a routine whose AC result is copied to one returns a shift (`shift_pair` when IO comes back too). Where its word lies is layout: a field the declarations lay out as a data word (`fields`, or `slots` of a collection) is run by `xct` where it is used (`xct sh0`), and holds the unset shift (`hlt`) on the tape when it has no initial value, or the code of its initial count; any other is the instruction at its one use, run where it stands (`mi1`). Setting it to `popcount(w & m)` fills the code's count field at run time (`CODE(t, POPCOUNT(w & m))`, `m | (scl`); setting it to a field held as the same code copies the word (`lac .` from the table, `dac sh0`). `runsc` refuses a held field that one Processor both writes and reads.
- `held_as_code` on a collection field of an enum: the run form. The field's use is the dispatch of a `[[code]]` walker, so each slot is held as its member's arm, laid end to end (above, and the rules below).
- `[[place]]` with `store` and `loaded`: a JSP routine that stores IO through the cursor into the collection held as code, and steps it, once for each word of a run (`ocs`: `dio i oc / idx oc` twice). The word and the run's length come from the members' code as `pdp1cc` compiles it: the one word the members hold in a row, every run of one length (`rcl 9s`, twice). None, or more than one word or length, is a BindError. Each such run in a member's code is stored by a call of it; IO takes the word (`REPEATED`) after the Processor `loaded` (`lio (rcl 9s` as each code is taken). That the routine exists, and where IO is loaded, are code layout, as `args_done` is.
- `[homes]`: fields held in a shift instruction's address field. `"table"`: a pointer in the address field of the `xct` that runs one shift of a table (`msh, xct .`); the table's entries are the code of the field's use (as `held_as_code`) for each count the RUNS source sets the field to, in source order, and a `[[place]]` with `shifts` lays the table out. Setting the field to the next entry steps the pointer (`idx msh`), to the first sets it (`law mst / dap msh`).
- `[encoding.<enum>]`: the word each member is: a number, or a routine's address, with the sign bit when `sign` is set (the object does not collide). A member no declaration encodes is encoded by `runsc`: the routine a `match` arm runs for it, as every match is a jump through the field's word (hc1d's state word: `sett pfu, s1`, then `govia pfu`), else its index in the enum, so a two-member enum is 0 and 1 (DDT's typing state in program flag 1: `clf 1`, `stf 1`, `szf 1`). A member with `sign` or `literal` takes its routine from its arm the same way.
- `[streams]`: the instruction that takes a stream's values, its first in AC and its second in IO: `dpy` plots a point; `hlt` shows the two on the console lights, and must be followed by the Network's `wait`, which the halt is.
- `[encoding.<enum>]` may also encode a member of an enum held in a program flag as 0 or 1.
- `pdp1/devices.toml`, `[console]`: a field read by an instruction of the console (`lat`, `control_boxes`), not from core. `or_into_io`: the device ors into IO, so IO is cleared first. `{ sense = n }`: a field the console's sense switch n holds (`szs`), an enum encoded as 0 and 1. `[lights]`: a field held in a program flag that lights on the console. `[[start]]`: a start address (`at`) and the top Network the operator's start there fires; `tape = true` on the tape's own start. With no `machine = "start vectors"`, the Network is laid out at its start address, its first word where the start goes (`start 500`).
- `[flags]`: a field held in a program flag; setting it to the member encoded as 1 is `stf`, to the one encoded as 0 `clf`.
- `pointers`: fields that hold addresses, which the C dialect types as `word *`.
- `[addresses]`: a field that always holds an address the layout fixes. `"after table"`: from the first word after the table, for the field's count of words.
- The table: Records laid out field after field, each field's slots together, from one array, where a `[[place]]` with `table = true` lays it out; the loop that clears the whole table steps a cursor of its own. `runsc` names the array `table_words` and the cursor `table_clear`; the names never reach the image. The table's Records are the collections whose fields have a walk's cursors, in the order the source declares them: a cursor is a pointer the walk steps through the table, one per field. The music player lays its voices out the same way (`b`, `n`, `t`, `a`, `p`, four slots each) and walks them by pointers held in instructions' address fields (`c0n`, `c0t`, `c0a`, `c0p`), set from the voice number in the layout's order.
- `[walk]`: the cursors' walk over the table's slots. The cursors are set after the Processor `set_after`, each from the table's start in the table's order. `index` is the field whose cursor steps last and ends the walk. `homes` and `home_in` say which instruction holds a cursor homed in this unit: the first one of the unit that reads or writes the field, or the first one in the named Processor. `carry` names `[[code]]` routines whose jump the walk loads into its home as that walk begins. The word is the one the walker starts from: its slot must be a field at the routine's slot (`let at = ships.outline[slot]`) that holds a place in the code (`[into]`) and has a cursor. `runsc` refuses the carry unless every calc that reaches the jump runs after that walk in the same slot, under guards that hold for its routine word, and nothing the slot runs writes the field. So a house rule that keeps a ship out of the collision walk is a BindError that names the jump and the guard, not a different game. `stray` is a cursor no field has, stepped after the named field.
- `repeat`: the Network the PDP-1 runs again when a firing ends, as the host does.
- `[[place]] exit = "<name>"`: the shared exit of the unit's JSP routines (`srt, jmp .`), laid out where it stands. Every block of the unit that runs off its end jumps there, and it returns to the caller of the JSP routine that entered the blocks. It replaces `repeat` for the unit.
- The cursors on the slot a field holds, not on a routine's own slot (`launch.slot`: the free slot a new torpedo takes). Each is homed in the first instruction of the unit that uses it. Setting the field to 0 sets the first cursor to the table's start (`init sr1, mtb`). The rest are set in the table's order, each from the one before (`law nob / add sr1 / dap ss3`, then `add (nob / dap ss4`).
- `[encoding.<enum>]` with `literal = true` on a routine member: its word is taken from a constant (`lac (tcr`) where the others are built by `law`. The two are the same word; which the original wrote is an encoding.
- `[walk] homes` also serves a unit that holds no walk: the cursors the main loop steps whose homes are in this unit's instructions (`mom`, `mth`, `mco`).
- `[inverse_skip]`: `"<field>" = "<block>"` names one test: the `if` whose guard reads the field and whose else runs the BLOCK Network. That test jumps to the block when it fails, with its own skip and the i bit flipped (`spa i; jmp mdn`), and falls into its arm; undeclared, the same test is `sma` with the arm laid out after a jump. Which word the 1962 programmer wrote for one condition is an encoding. `runsc` refuses an entry whose test is not one sign test of the field (`< 0`, `>= 0`) with an else of that one jump and an arm that ends in a jump, an entry that names no test, and one that names more than one. Spacewar's restart check is the one use; the user raised the count for it (decisions row of 2026-11-10, "the game text *must* be pure").
- `[into]`: a field that holds a place in a collection (`outline_call.code`, a slot of `outline_code`) holds that place's address; for a collection held as a run of code, the address of the slot's code. The C dialect types it as a pointer. A number set into it is the address of that slot; reading the collection at the field is reading through it, and stepping the field steps the pointer (`idx`). It is storage.
- `[homes]` with `"pointer"`: an `[into]` field held in the address field of the first instruction that reads through it (`ocg, lio .`).
- `[addresses]` with a collection's field: the collection lies at an address the layout fixes, not at a place of its own. `"after table"`: from the first word after the object table (`outline_code`, nnn). `runsc` reserves the collection's RUNS count of words there, or for a collection held as a run of code its `[code_words]`, so the units after it lie past them: the star catalog lies at `6077/` because `outline_code` takes 02105 words, and a different count builds a different image.
- `[code_words]`: the words a collection held as a run of code takes, which `runsc` reserves (a slot's code is as long as its member's arm, so the RUNS count of slots does not give it).
- `[[place]]` with `slots`, `range` and `reserve`: the slots `range` of a collection's field laid out as data words with their RUNS initial values, then `reserve` words of room no rule reads (the five spare words after each outline, for an operator to make it longer).
- `[share]`: a field that lives in another field's word (`central_star.slope_x` in `spaceship.gravity_x`'s, `\bx`). `runsc` refuses it unless, in every firing of a top Network and on every path, each field is set before it is read with no write of the other between (the shared words check, below).
- `data`: fields laid out as data words inside the routine's code, at its first point control cannot reach (`ocm`, `ocn` after `oc`'s return).
- `args_done`: the Processor after which the routine steps its return address past the words after its call (`idx ocx`). Where it does so is a choice of code layout; pdp1cc needs AC dead there.
- `pulse = true` on a routine: its points ask the display for a completion pulse (`dpy-4000`, at intensity 0). Each point waits for the one before it (`ioh`), and a routine that runs it waits for its last after the run. It is the display's handshake (`bpt`, the central star's line).
- `flags`: locals held in a program flag (`{ half = 6 }`), an enum encoded as 0 and 1. Setting one is `stf` or `clf`; a guard on it is `flag(n)`.
- `homes`: locals held in the address field of the instruction that reads through them (`{ star_x = "pointer" }`, `fin, lac .`). The instruction is the one the first read takes it into: IO for a point's y (`lio`), AC otherwise. On the tape the address is 0, as the source writes such an instruction with no operand.
- `into`: locals that hold a place in a collection (`{ star_x = "star_catalog.words" }`). A place by number set into one is that slot's address. Two places compared, one held by a homed local, are compared as its home instruction (`I_LIO(p)`; `I_LIO(++p)` when the step just before is the comparison's).
- `data` may name locals and a collection's field. Each copy of the Processor that holds them (a Processor laid out at each run, `show_magnitude`) gets its own: its homed locals, its data locals, and the slots of the field it names by number, laid out at the copy's end. A data local is encoded as the home instruction it is compared with, at address 0 on the tape (`fpo, lio`).
- `arms = "apart"`: in the routine's loops, the first arm of each if with an else lies apart, after the loop, and jumps back to the code after the if (to the loop's top when the if ends the loop's body); an arm that is only a break is the jump itself. The loop's breaks are one jump out, laid out at the first break in the source, which the others jump to. Data words of the copy follow (`dislis`: `fgr`, `fuu`, `flp` after `jmp fin`; `fx`).
- `exit_after`: the routine's exit lies right after the named Processor, in the skip of the guard that follows it (`isp bcc / bcx, jmp .`). Each if with no else that ends the routine, or ends such an if's arm, is laid out as a guard: its test, negated, leaves the routine, and its arm follows in line. The returns after the exit jump to it.
- `tails = "shared"`: paths of the routine that join and end with the same words share one copy (`SHARED_TAILS`, pdp1cc's cross-jumping): the path that falls into the join keeps them, and each other jumps to the first word they share, which may stand mid-statement (`lac (y / jmp oce`; DDT's `lac X / jmp ssn`). It is code layout: the words that run are the same.

These rules read the Network as written today, which is structured code: its line order states the original's order, its loops may leave mid-body (`break`, `continue`), and an `if` need not have an `else`. The EGS vision is a graph: the Network is the explicit wiring of Records to Processors, execution order is derived from it and never authored, each tick is a DAG, guards form a complete partition, and a bounded fold has no `break` or `continue` (`../../.github/CONTEXT.md` 162-170, 188-206, 344-358). Today's source falls short of that graph. How the compiler reaches the original's layout from such a graph is open.

`runsc` lays code out by rules of its own, from the shape of the RUNS source, the same for every program's declarations:

- A value moves from AC to IO by the `swap` macro, `rcl 9s` twice (`SWAP`): Spacewar's (`swap`) and Minskytron's own (`rcl 9s / rcl 9s` before `jsp gsh`).
- A loop whose last statement is `if c: break` tests at the bottom and jumps back to the top while `c` fails (`count \mxc, mz1`). A break before it jumps past the loop, as a rotated loop's does (`dzm i \mfu / jmp sq9`, then `count \src, sq7`); a break of a loop that is the routine's last statement is its return.
- `set x = x + 1` followed by a test of `x` against 0 is one index-and-skip (`isp`).
- A fold counted by a counter: `for _ in 1 .. -f:` whose body ends in a step of `f` (`set f = f + 1`, or a run of a Processor that is only that) and sets `f` nowhere else. It is the index-and-skip loop on `f` (isp): the body, the step, and a test that leaves when `f` reaches 0. The fold runs `-f` passes and so does the loop, so `runsc` takes it only where `f` is known below 0 and not -0 when the fold starts: inside `if f < 0:`, after a step of `f`, or after a set of `f` to a constant. Five sites: the square root, the spare-time loop, a ship in the star, the explosion's dots (a Network) and head_out (`let angle_steps = -3`). `tools/folds.py` holds this rule and the next two.
- A loop's first pass written before it: the statements X just before `if f < 0:` around such a loop, whose body ends in X and the exit test, are the loop's first pass, so the loop starts with X and the `if` goes. What the body holds before X is laid out after the exit test, each trailing `if` with no else failing to the head. Four sites: the explosion's dots (`count \mxc, mz1`), the spare-time loop (`count \mtc, .`) and a ship in the star (`count \ssn, .`), where X is the whole pass; the square root (`sq3, isp sq1 / jmp .+3`), where X is the step and the rest follows the test.
- A guarded fold: `for _ in 1 .. n:` whose body is guards on one test H, such as `if drawing == going:` or `if pass == 1 or <test>:`. Once H fails no pass does anything, so H stays failed. Its count is the bound the loop it stands for keeps and compiles to nothing, so `runsc` takes it only counting from 1, where a mutant can only raise it. `runsc` follows what each path through the body knows (a constant set, a test passed or failed, the sets of a Processor it runs) and lays the fold out as a loop: a path that ends the pass with H known false ends in a break; one that skips the rest of the pass with H known true ends in a continue; where H is unknown at the end, the loop tests it at the bottom. A guard a path decides is dropped there, and a local that only decided guards read is dead. Six sites: sine_reduce, draw_star, show_magnitude, draw_outline (a local of `enum progress`), compile_outline and the exhaust (Networks, `if pass == 1 or <test>:`).
- When an `if`'s else arm ends in an `if` whose arm ends with the statements of the first arm, those statements are laid out once, at the end of the inner arm, and the first arm jumps to them (`count i ma1, hp6`).
- `set a = -a` or `set a = 0` on an AC local followed by `set f = 0` on a place in IO is one instruction, `cma cli` or `cla cli`. So is `set f = 0` on a field of a register Record, which is in IO from there (DDT's `listen`, `cla cli clf 1`, then IO carries the typed character on). A field some routine reads is an IO register local of its own; one no routine of the program reads holds nothing and compiles to the IO half the routine already names (`cma cli` in the explosion, whose dots shift IO out).
- A guard joined with `and` and `or` is laid out as jumps: each test jumps to the arm it decides, and the last falls into the first arm. A sign test that jumps on its failure keeps its own skip with the i bit flipped (`spa i`).
- A guard on one enum field whose members' words decide it by sign and zero is a test of the word: `!= m` for every member encoded as 0 is `!= 0`, for every member encoded with the sign bit `>= 0`, for both `> 0`. The guard reads the field into a local; when the arm's next guard on the field or jump through it comes first, AC keeps it, else it moves to IO.
- `field == m` for a member encoded as an address is the member's word xor the field. Two guards in a row on one comparison share the xor.
- Two sets in a row of one value, not a name or a number, load it once, when the value does not read the place the first set writes.
- `let v = ...rar(e, n)...` with `e` not a local takes `e` into `v` first: pdp1cc rotates a local in place.
- A `match` whose arms each run the routine their member is encoded as is a jump through the field's word (`lac i ml1 / dap .+1 / jsp .`).
- A Processor that sets fields of the table to their zero word in every slot is the clearing loop over the whole table. A clearing loop may also clear a word whose old value is dead: a table field the Processor leaves alone is cleared with the rest only when `runsc` proves that every path on from each run of the Processor sets each of the field's slots before anything reads it. The run must be a statement of a Network's body. The path follows what comes after it there, through the Networks and Processors it runs and both arms of each if. A slot is set by a top-level `set field[k]` with `k` a number, and any other mention of the field first is a read. `new_game` clears the table and then sets `ship_outlines.outline[0]` (`outlines_from_free_core`) and `[1]` (`second_outline`), so `clear_tables` leaves the outlines alone and the one loop (`clear mtb, nnn-1`) still clears their words. The Macro assembler does the same: its loop at 2143 clears 4621..4650, and the next store, at 2150, writes 4621 (`russell2_macro_sa0`, the corpus's tapes).
- When an arm ends in a jump, what follows the if is its else, laid out after it.
- A collection field no routine sets is a table of constants: its slot named by a number is that number in each copy of the routine that names it, as a macro's arguments are in each expansion (`magnitudes.first[0]` in `dislis 1j, 1q, 3`: `law 1j`; hc1d's `copy nt, kt, 44`: `law nt`).
- A call's AC result that the routine stored into a word as its last statement is that word's value for the statement right after the call, which reads it from AC, as Minskytron's `plot_a` plots the `xa` that `step_a` just stored (`dac xa / lio ya / dpy-i`). The torpedo plots the x that `diff` stored (`dac i mx1 / dispt i, i my1`).
- A Processor that returns, run inside a walk or before other routines, returns by a jump to its end.
- A `match` on a field in a pool word is a call through it (`jsp i \cwg`); the routines its members name return one result, in IO. A member encoded as a JSP slot runs the routine the slot jumps to.
- Setting a program flag, then a new AC local to 0, is one instruction (`clf 6 cla`). Two zeros plotted are cleared by one (`cla cli`).
- `set v = ral(v, n)` on an IO local rotates IO in place (`ril`).
- A guard on a field held in a sense switch or a program flag is the machine's test of it: `sense(n)`, `flag(n)`.
- A register field set from a half of a call's pair result is that half, with no move.
- An undeclared Network that a routine runs as the last thing of several branches is laid out once, where the last of them runs it, and the others jump to it (`jmp bsg`).
- `stop` is a halt that halts again when continued (`hlt / jmp .-1`).
- A loop that steps a field holding a slot, then stops when it reaches a slot by number, is a search: one index of the first cursor and a test of its home instruction against the one past the last slot (`index sr1, (lac mtb nob, sr1`).
- In the slot a field holds, a store of a plain value goes through IO while AC builds the cursors' chain; any statement that wants AC first finishes the chain. `set f = f & 0770000 | n` with n an address is a store of the address part (`dap`).
- A pool field is declared by each unit that names it; they are one word. One that holds a member of an enum whose members are all encoded as routines holds a routine's address, and is declared a pointer to the routines' type, which the enum names (`controls.source`: `typedef io_word control_source(void) JSP`).
- A cursor the unit's code names and does not hold itself is declared as another unit holds it: homed in an instruction (`extern HOMED`), else a pool word. The object table is declared where another unit lays it out.
- A member written into a collection held as a run of code (`set L.f[p] = m`), the held fields its arm holds at the same slot, then `set p = p + 1`, is the member's code stored at p (`LAY_OUT`): `runsc` emits each member's arm as a `TEMPLATE` function whose parameters are the register fields the walk keeps in AC and IO, `pdp1cc` compiles it with its ordinary selector, and the store is each word through p (`lac (w / dac i p / idx p`), a held field's word from its value (`lac ocm`), and a jump within the arm built from p in the routine's jump word (`add (4 / dap ocn / lac ocn`). The jump word is laid out with the routine's data when a member's code, as `pdp1cc` compiles it, jumps within itself, and only then: `runsc` compiles the unit once, reads `pdp1cc`'s words for the members (`template_words`), and compiles it again with what they need.
- A place held as code (the walk goes on from it, or it is copied to a field that does) is the jump to it: a data word that jumps to itself until it is set (`ocm, jmp .`), set from a place by its address (`dap ocm`).
- `set c[p] = v` then `set p = p + 1`, with p an `[into]` field of c, is one store through the pointer and a step (`*p++ = v`: `dac i p / idx p`).
- An if-chain with no else whose guards test one value for `== n`, or an `or` of such tests, over 0 to some n, is a jump table (`switch`, `add (T / dap J / J, jmp .`). The arm of n lies in the table and must end in a jump; the other arms lie apart. The first lies right after the table and falls into the code after the chain; the rest lie after the routine's code, each jumping back to that code. A Network that the arms run last is laid out in the first arm, and the others jump to it. A jump after an arm's last if/else goes into both of its branches. The arms share their locals, which are declared at the routine's top.
- A loop whose body ends with `if c: X`, no else, is laid out with the test at the bottom: back to the top while c fails, then X. When X ends with the statements just before the loop, they are laid out once and X jumps back to them, the loop's second entry (`jmp ocj`, then `och`). A break of a loop that is the routine's last statement is its return.
- An entry word of another unit's routine is, to the caller, AC: a value carried into the call and out of it (`jda oc`).
- A counted loop from a local up to n, that does not read its index, is a jump into a run of n + 1 copies of its body past as many as the local says (Duff's device, `bjm, jmp .` into `bds`). The jump's address is set right after the local's last set before the loop, and `runsc` refuses a local set anywhere else.
- A program flag set, then a new AC local and a new IO local set to 0, is one instruction (`cla cli clf 6`).
- A plain loop that ends the routine leaves it through its breaks: each is a return.
- An initial value may be an expression of numbers (`8192 - 1537`, `371 << 8`); the word is its value.
- A place just past a collection's last slot has an address too (`lio Q+2`).
- A local of a routine laid out once that is held in the address field of the instruction that reads through it (`homes`) is one word of the unit (`dap .+1 / lac .`).
- A read of a collection by a slot index held in such a local (`homes`, no `[into]`) adds the index to the word of the collection's address and reads through the sum (`add gsc / dap .+1 / lac .`). A `[[place]]` with `base` lays that word out (`gsc, gst`). It is layout: the source holds the index, never the address.

A `[[place]]` may instead lay out words that the PDP-1 and its operator need and that no game rule reads. `runsc` knows each kind as the PDP-1 back end, the way it knows `jda`:

- `machine = "sequence break"`: words 0-2, where a sequence break saves AC, PC and IO (not punched), and word 3, a jump to the flush. `machine = "sequence break flush"`: the flush, which resumes the interrupted program. Play never raises a sequence break (`docs/c-lift/README.md`: the frame check never runs these words).
- `machine = "start vectors"`: a jump to each top Network at its start address, from `pdp1/devices.toml`.
- `jsp_slot`: a JSP routine the operator may rewrite in place, laid out `at` an address. By default it jumps to `jump` and returns what that returns, in the register that returns it (`runsc` takes it from `jump`'s result: the routines a field may name share one type); `reserve` words of room follow it.
- `machine = "constants"` and `machine = "variables"`: where the assembler lays out its literal constants and its pool words, each at most once; a program with none has neither. `machine = "patch space"`: `reserve` words of room for the operator's patches (`p, . 200/`). No rule reads any of them as a place: a constant is a number in the RUNS source, and a pool word is a field.
- `table = true`: the object table's words. The tape does not load them and a new game clears them before anything reads them, so `runsc` requires each table field's RUNS initial value to be its zero word.

A field with no data word of its own (an entry word, a register) has no value on the tape, so its RUNS initial value must be 0; `runsc` refuses any other.

## Network files

A network file (`runs/arithmetic/*.net`, `tools/graph.py`) states places, transitions and arcs, and no order and no word. `runsc.pdp1_program()` lowers each to a Network for the PDP-1 (`lower_for_pdp1`); no declaration is added for it. A bundle's inputs and outputs are the fields of its call Record, `<bundle>_call`, and its own declaration (`[[place]] routine = <bundle>`) is the one above.

- Words. The two ends of an inout share a word: a fresh value takes its dead predecessor's word. Then the two ends of a copy share one when both sides of a test write its target (`give_high`, `keep_low`). Two places never share when the declarations give each its own word, or when one is the high half of a pair operation (held in AC) and the other has a word in memory. A class of places that share lives in a word the declarations give, else the word of the bundle that takes or gives it. Else: a value that must be in memory (the operand of `mus` or `dis`, or what a bundle takes `byname`) takes a memory word of the network's call Record (an `entry`, `cells` or `fields` word); the low half of a pair operation takes the routine's IO word (`io_param` or an `io` field); any other value is the Network's own scratch in AC, else the IO word. Of these choices, `runsc` keeps the first under which some order reads every value from its word before the next value takes it.
- Order. Of the orders the wiring allows (each transition after the writers of what it and its guard read; each side of a test one block; an inout of the network written after its reads), `runsc` keeps those in which no value is read after its word took another, and none read in AC after AC took another (a copy or a constant into IO, or a copy whose ends share a word, leaves AC alone). Among the transitions that may go next it takes an unguarded one before a test's side, then the one that reads the value the call hands over earliest (`entry`, then `io_param`, then `byname`), then names, which decide nothing in the image.
- A copy whose ends share a word compiles to nothing. A side of a test that only sets the routine's `skips` field is written before the test, as an empty `else` would compile to a jump.

## Names

A C function is named after its RUNS routine, and a field's word `record_field`. Two fields that share a word (`[share]`) take the name of the one they share. A copy's own locals and slots take the copy's number or the slot's (`star_x_1`, `magnitudes_cursor_0`). The names do not reach the image.

## What a program's declarations may not say

No game logic. A program's declarations have no expressions, no statements and no number that the game computes with. Every word of the image that the game's rules decide comes from the RUNS source, and every RUNS reference is compiled as the field it names.

`runsc` enforces the parts of this it can decide before it writes C:

- It compiles only RUNS the evaluator accepts: `runs.check` (what each kind may say, the contracts, a static scope check of names, fields and runs, each Processor's `reads:` and `writes:` against its source in both directions, the type of each expression, and no routine that fires itself).
  Today each Processor names the Records it reads and writes, and `requires:` is a precondition. In the EGS vision a Processor knows nothing of Records and the Network alone draws each wire (`../../.github/CONTEXT.md` 166-169); `requires:` names inbound boundary Records, and a precondition is a DIGS boolean a Processor declares (272-275, 372-384). Today's keywords disagree with the vision's. How the source closes that gap is open.
- Every key of a program's declarations is one it knows, with a value of its kind, and every value names a field, routine, member or local of the RUNS source. A key the RUNS needs and no declaration gives is a BindError. A name a program's declarations give a C word of its own (a cursor, the table, a block, an exit, a slot) names nothing else: no other such word, no routine, Record or field, and no word of C or of the dialect's header. A `[share]` lives in a word of its own, the table's Records are collections, a cursor is homed in one unit, the walk's index has a cursor in each walk, and a console field is read by an instruction or held in a sense switch. A member's name means the member of the enum of the field it is stored in or compared with, as in the evaluator.
- Shared words. Several RUNS names can live in one word: an entry word and its `cells`, a `[share]`, and names `runsc` compiles to one C name (a local kept in the register a field arrived in, the halves of a pair, a call's result). `runsc` follows, through every routine and across the runs between them, which names each such word holds: the last one written and those copied from it since. A top Network starts with none, and a routine's register parameter holds its field only where every run of it sets it just before. A read of a name its word does not hold is a BindError, and so is a routine that returns a result field whose word holds another name, or leaves such a word holding only its locals, unless a bit-level pass proves the Processor's effects use no bit of the value read (`draw_jump` and `plot_particle` shift IO's old value out).
- `carry` goes through the field the RUNS jump names, and only where the walk loads it for every slot that jumps (`[walk]` above). A skip return is set on every path, the skip member last.

`tools/check_compiled.py` checks the rest by mutation, in every routine and field a program's declarations compile. It changes each number and initial value, each field reference to every other field of its Record (of its type and of another) and to the field of its name in another Record, each operator and enum member, and each run to every other routine of its kind and arity. It negates each guard, swaps an if's arm with its else and its first two arms, and swaps each two arms of a match. It deletes, duplicates and swaps each statement with the next, and moves it to every other place in its block. After each let and set it inserts a set of each other place the routine sets, to the same value, and a step of its own place (`set p = p + 1`), and inserts that step before it too. It makes each top-level set of a field a local of the field's name, and deletes each Record of each `reads:` and `writes:` and each `requires:`. In each program's declarations it deletes each key line, each section and each element of a list or inline table, and replaces each value: a quoted name by every other of its shape in the file, a number one up and one down, a flag flipped. A program's declarations mutant must change the image or be refused, so no key, element or value is dead; one that builds the image passes only when the value was a name the declarations give a C word, which never reaches the image. A RUNS mutant must change the image, be refused with a BindError or rejected by the evaluator, or be shown the same game: the evaluator fires the mutated routine, and failing that each declared routine that compiles it, on 200 seeded Record states (a quarter of the words drawn from the edges: 0, -0, +-1, the extremes) and on up to 60 Record states as play leaves them before its firings (60 games the evaluator plays from the tape's words with random power-on words, console switches and control boxes), and the mutant passes only if every firing leaves the same Records, points and errors, with at least 50 running clean through the mutated routine. A loop's bound is RUNS's own check and compiles to nothing: a mutant of it passes when every firing is the same or stops at the bound it states. A `requires:` deleted passes when every firing it lets run is the same and it stops some firing.

Where play observes the layout, the RUNS source states the layout, and the declarations follow it (`INTENT.md`, "Exactness, glitches, and the machine").

## Checks for a converted unit

A unit counts as converted when all of these pass:

1. `uv run python tools/runsc.py` prints `identical to the original`.
2. `uv run python tools/check_compiled.py` passes.
3. Each RUNS routine of the unit matches SIMH running the original, through the evaluator, over every input or a seeded random sample with the edge cases (`tools/check_*.py`).
4. The checks of earlier units still pass (`tools/check_all.sh`).
